## Review outcome

Problem: Heartbeat-run gateway tokens (minted with 1-hour expiry) are rejected after 60 minutes even if the agent's run is still actively running, causing reconnections during long runs to fail with 401 Unauthorized. Furthermore, the rejection reason code is not recorded in the HTTP request log.

Implementation: Binds run token lifetime to active run state (`ACTIVE_GATEWAY_RUN_STATUSES`), preserves configured expiry for non-run tokens, logs structured auth failures with reason codes, and exposes the reason code in the request log.

## Regression and touched-line verification

- Regression tests (`server/src/__tests__/run-gateway-token-lifetime.test.ts`):
  1) `a run-bound token presented more than an hour after minting, while its run is running, is accepted`: fails on base (rejected with 401 `gateway_token_expired`), passes on head.
  2) `the same token is rejected once the run has finished`: passes on base and head (rejected with 401 `gateway_token_run_inactive`).
  3) `a token that is not run-bound still expires at its expiresAt`: passes on base and head (rejected with 401 `gateway_token_expired`).

# fix(server): drain in-flight adapter runs during shutdown

Unsent discussion draft. The operator must decide whether and where to post it.

**Problem**

The server can exit before adapter stop acknowledgements settle.

**Proposed outcome**

Stop admitting execution work, request graceful adapter stops and await settlement within the configured deadline.

**Existing work and scope**

Merged PR 14028 improves drain-time wake handling but does not establish this complete shutdown drain outcome. No retirement proof.

**Decision needed before a PR**

The default increase from 5 to 60 seconds needs a compatibility decision; admission race and deadline validation remain defects.

**Acceptance still required**

Needs races between shutdown and actual dispatch/native resume/reaper, finite deadline validation, supervisor grace documentation and real child acknowledgement evidence.

**Compatibility concerns**

Current flag does not fence every claim/dispatch/resume path. parseInt accepts malformed values. The global default increases shutdown duration for every deployment.

## Thinking Path

> - Paperclip manages AI agents and their work.
> - Managed MCP gateways give a run access to its permitted tools.
> - These clients carry gateway credentials rather than board or agent API credentials.
> - Actor middleware rejects the managed handshake before the gateway can verify that credential.
> - Public initialized notifications also accept invalid credentials without verification.
> - This change sends only the managed protocol POST to the gateway verifier and authenticates initialized notifications.
> - A valid notification does not charge initialization twice or write token usage and run identity.

## What Changed

- Restrict the managed gateway handoff to POST on the exact UUID endpoint with a `pcgw_` bearer. Clear implicit board authority before gateway verification.
- Preserve the public endpoint's default actor and ordinary actor authentication on other routes.
- Verify initialized notifications through the existing token and run checks. Return an empty 202 on success, an empty rejection status on authentication failure, or an empty 500 on unexpected errors.
- Skip successful-notification usage, identity and protocol-counter writes. Keep failed-authentication throttling and audit behavior.
- Add real PostgreSQL regressions for both deployment modes, malformed credentials, lifecycle invalidation, route boundaries, state preservation and database failure.
- Isolate two Codex resume test HOME directories and document the managed MCP contract.

# fix(tool-gateway): bind run gateway token lifetime to active run state

## Thinking Path

> 1. **Understand the Problem and System Context:**
>    - Paperclip mints MCP gateway tokens for heartbeat runs (`subjectType: "heartbeat_run"`), including the `paperclip-assigned` runtime server and managed gateway tokens.
>    - These tokens are minted with a fixed 1-hour expiry (`expiresAt: now + 60 min`).
>    - During execution, autonomous agent runs can legitimately exceed 60 minutes (e.g. 82-minute run `1a267f85`).
>    - When an agent reconnects or sends new tool calls/initializations after 60 minutes, `namedGatewaySessionFromBearer` in `tool-gateway.ts` rejected the token with 401 `gateway_token_expired` because `expiresAt <= Date.now()`, even though the run was actively `running`.
>    - Additionally, the HTTP request log recorded only the status `401 Unauthorized`, hiding the `reasonCode` from operators inspecting server logs.
> 2. **Design the Minimal, Direct Fix:**
>    - **Token Lifetime Binding:**
>      - In `namedGatewaySessionFromBearer` (`server/src/services/tool-gateway.ts`), exempt tokens with `subjectType === "heartbeat_run"` from the static `expiresAt` check.
>      - The token's validity is governed by `ACTIVE_GATEWAY_RUN_STATUSES.has(run.status)`: valid while the run is active; rejected with `gateway_token_run_inactive` as soon as the run leaves active status.
>      - Tokens that are not run-bound (e.g. `subjectType: "gateway_client"` or `subjectType: "agent"`) continue to enforce their configured `expiresAt`.
>    - **Operator Observability:**
>      - In `recordNamedGatewayAuthFailure`, emit a structured `logger.warn` log with `event: "named_gateway_auth_failed"`, `reasonCode: input.reasonCode`, and gateway identifiers.
>      - In `handleMcpGatewayProtocol` (`server/src/routes/tool-gateway.ts`), set `(res as any).__errorContext = { error: { message: `${err.message} (${err.reasonCode})` } }` so the HTTP request logger formats the request log line with the exact failure reason code.
> 3. **Verify:**
>    - Regression tests in `server/src/__tests__/run-gateway-token-lifetime.test.ts` prove:
>      1) A run-bound token presented > 1 hour after minting while its run is running is accepted.
>      2) The same token is rejected with `gateway_token_run_inactive` once the run finishes.
>      3) A token that is not run-bound still expires at its `expiresAt`.

### Issue Summary: MCP gateway tokens expire after 1 hour during active heartbeat runs

**What happened?**
During long heartbeat runs (e.g. runs running longer than 60 minutes), agents reconnecting or issuing MCP protocol calls through their assigned MCP gateway were rejected with `401 Unauthorized` ("Gateway bearer token is expired or invalid"). The tokens had been minted with `expiresAt: now + 60 min`, and `namedGatewaySessionFromBearer` unconditionally checked `expiresAt <= Date.now()` regardless of whether the associated heartbeat run was still actively running. Furthermore, the rejection reason was absent from the HTTP request log.

**What did you expect to happen?**
1. A heartbeat-run gateway token (`subjectType: "heartbeat_run"`) is accepted for as long as its heartbeat run is actively `running`.
2. Once the run terminates (succeeds, fails, cancels, etc.), the token is rejected with `gateway_token_run_inactive`.
3. Tokens that are not run-bound continue to expire at their configured `expiresAt`.
4. Authentication failure reason codes are logged and visible in HTTP request logs for operator troubleshooting.

**Steps to reproduce**
1. Start an agent heartbeat run and mint a run-bound gateway token with `subjectType: "heartbeat_run"`.
2. Present the token after 60 minutes while the run is still in status `running`.
3. Observe that the gateway rejects the request with 401 `gateway_token_expired`.

**Paperclip version or commit**
`master` at `01d9a121859a3d8298dce91452f75516e837e819` and release tag `v2026.916.1`.

## What Changed

- `server/src/services/tool-gateway.ts`:
  - In `namedGatewaySessionFromBearer`, exempted `subjectType === "heartbeat_run"` tokens from the static `expiresAt` check, letting active run state (`ACTIVE_GATEWAY_RUN_STATUSES`) determine validity.
  - In `recordNamedGatewayAuthFailure`, added structured warning logging (`logger.warn`) with `event: "named_gateway_auth_failed"`, `reasonCode`, and gateway identifiers.
- `server/src/routes/tool-gateway.ts`:
  - In `handleMcpGatewayProtocol`, set `__errorContext` on `res` with the error message and `reasonCode` so HTTP request logs record the failure reason.
- `server/src/__tests__/run-gateway-token-lifetime.test.ts`:
  - Added regression test suite verifying run-bound token acceptance beyond 1 hour during active runs, rejection upon run completion, and standard expiration for non-run tokens.

## Thinking Path

> - Paperclip is the open source app people use to manage AI agents for work
> - A running agent gets a run-scoped `pcgt_*` session token for the tool gateway endpoints `GET /api/tool-gateway/tools` and `POST /api/tool-gateway/tools/call`
> - Those routes read the token only from `X-Paperclip-Tool-Gateway-Token`. When an agent sends it as `Authorization: Bearer pcgt_…`, the actor middleware rejects it as an invalid agent token first
> - Also, the session lookup accepts a `pcgw_*` gateway token on these endpoints when the request carries no gateway locator. A gateway token whose allowed actions exclude `tools/list` can then list tools through the session endpoint
> - This pull request accepts a `pcgt_*` bearer on those two endpoints and rejects gateway tokens there
> - The benefit is that agents can use the standard bearer transport for their session token, and each token family works only on its own endpoints

## What Changed

- `server/src/middleware/auth.ts`: a `Bearer pcgt_…` request to `/api/tool-gateway/tools` or `/api/tool-gateway/tools/call` passes to the route, and the actor is `none`. Any other credential on those paths (board session, board key, agent JWT) keeps normal actor authentication, including the JWT run-header audit and the terminated or pending agent checks.
- `server/src/routes/tool-gateway.ts`: `gatewayToken()` reads `X-Paperclip-Tool-Gateway-Token` first. If that header is absent, it reads a `pcgt_`-prefixed Authorization bearer.
- `server/src/services/tool-gateway.ts`: `getActiveSession` rejects a `pcgw_*` token with `session_invalid` when no gateway locator is present. Upstream's full-token hash lookup and the revoked, expired, and run-active checks do not change.
- Docs: `doc/MCP-ACCESS-GOVERNANCE.md` documents both transports, the header precedence, and the gateway-token rejection. `doc/MCP-DEMO-SCRIPT.md` no longer says that `Authorization` is unused.
- Tests:
  - The Authorization bearer works for tools/list and tools/call through expiry (driven through the session row, without fake timers).
  - Revoked, cross-session, malformed, wrong-run, inactive-run, and cross-protocol tokens are rejected.
  - A gateway token is rejected on both session endpoints through the pre-existing header transport.
  - Agent JWTs are still authenticated on these paths.
  - Only a `pcgt_` bearer is read from Authorization.

## Thinking Path

> - Paperclip is the open source app people use to manage AI agents for work
> - Paperclip gives each Codex CLI run a managed MCP gateway, with a run-scoped `pcgw_*` bearer written into the run's `config.toml`
> - Codex reads MCP request headers only from `http_headers`, but the codex-local adapter writes the bearer under `headers`, which Codex ignores. The gateway never gets the credential (#10346)
> - When a client does send `Authorization: Bearer pcgw_…` to the managed route `/api/tool-gateway/gateways/<uuid>/mcp`, the actor middleware tries to verify it as an agent key or JWT and rejects it before the gateway can verify it
> - Also, the route answers `notifications/initialized` with 202 and never checks the bearer
> - This pull request writes `http_headers` and lets only a POST with a `pcgw_*` bearer on the managed route pass to the gateway's own verification. It also verifies the bearer on the initialized notification, with no rate-limit charge and no writes
> - The benefit is that a Paperclip-launched Codex run can initialize, list, and call tools through its managed gateway, and the credential boundary stays narrow

## What Changed

- `packages/adapters/codex-local/src/server/codex-home.ts`: write the managed MCP bearer as `http_headers = { Authorization = … }`.
- `server/src/middleware/auth.ts`: new clause for `POST /api/tool-gateway/gateways/<uuid>/mcp` with a `pcgw_` bearer. The actor middleware does not interpret that bearer, and the actor is `none`. The gateway protocol route verifies it. GET and other methods keep normal authentication. The existing public `/mcp/gateways/gw_…` clause does not change.
- `server/src/lib/uuid.ts`: one shared generic UUID pattern, used by the middleware and the gateway routes.
- `server/src/routes/tool-gateway.ts`, `server/src/services/tool-gateway.ts`: `notifications/initialized` verifies the bearer (new `verifyNamedGatewayProtocolNotification`). It does not charge the session-setup limiter, write `lastUsedAt`, or capture run identity, and it answers with a transport status and no JSON-RPC body.
- Tests:
  - `codex-home.test.ts` and `codex-local-execute.test.ts` pin `http_headers` and reject a bare `headers =` line.
  - `agent-auth-middleware.test.ts` covers the managed bypass, lookalike paths, non-gateway bearers, GET, the public path's actor, and a nil UUID.
  - `tool-gateway.test.ts` runs the full initialize → notification → tools/list → tools/call lifecycle through the real actor middleware, and covers the audit-filter UUID validation.

## Risks

- The bypass is limited to POST, to the exact managed path with a UUID, and to a `pcgw_` bearer. All other requests keep actor authentication.
- The UUID pattern for audit filters is now generic. It no longer checks the version or variant nibble, so ids from imported or seeded rows are accepted. A test covers this.
- The initialized notification now needs a valid bearer. Before, it always answered 202.

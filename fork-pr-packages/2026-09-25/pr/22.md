# fix(environments): release environment leases of terminal runs

## Thinking Path

> 1. **Understand the Problem and System Context:**
>    - Environment leases track sandbox allocations and locks for runs.
>    - Previously, when a run terminated through cancellation (`cancelRunInternal`), recovery sweep (`terminalizeOrphanedRunningRunCandidate` in `recoveryService`), or in-process completion without an active environment driver instance, its environment leases were left in `active` state with `releasedAt: null`.
>    - This stranded leases on terminal runs indefinitely, causing lease starvation and preventing subsequent runs from acquiring execution locks (`validateExecutionReconciliation` complaints, `getConversationOwnershipBlocker` retaining `execution_owner_active`).
>    - Upstream PR #13515 introduced `sweepOrphanedActiveLeases` to transition orphaned active leases of terminal runs to `pending_cleanup`. However:
>      1) It lacked process liveness checks: leases of runs whose processes were still actively running could be prematurely marked `pending_cleanup`.
>      2) For `local` provider leases, `sweepPendingCleanupLeases` failed with `Environment driver "local" does not support orphan sandbox teardown` and marked the lease `failed` with `releasedAt: null`, stranding the local lease permanently without manual DB intervention.
> 2. **Design the Minimal, Direct Fix:**
>    - Ensure environment leases are released on every terminalizing path once execution has stopped:
>      - In `server/src/services/environments.ts`:
>        - Update `releaseLeasesForRun` to query both `active` and `pending_cleanup` statuses, and accept `options?: { failureReason?: string; cleanupStatus?: EnvironmentLeaseCleanupStatus }` (defaulting `cleanupStatus: "success"`).
>      - In `server/src/services/environment-runtime.ts`:
>        - In `releaseRunLeases`, when `!environment`, release active/pending leases via `environmentsSvc.releaseLease(leaseRow.id, status, { cleanupStatus: "success" })` instead of silently skipping.
>      - In `server/src/services/recovery/service.ts`:
>        - Accept `releaseEnvironmentLeasesForRun?: (run: typeof heartbeatRuns.$inferSelect) => Promise<void>` in `recoveryService` dependencies.
>        - In `terminalizeOrphanedRunningRunCandidate`, invoke `releaseEnvironmentLeasesForRun` when terminalizing a run to `interrupted`.
>      - In `server/src/services/heartbeat.ts`:
>        - In `cancelRunInternal`: release environment leases after termination settles and `cancelled` status is written, before promoting next runs.
>        - In `releaseEnvironmentLeasesForRun`: guard against premature release if `processPid` is alive, `processGroupId` is alive, `runningProcesses.has(input.runId)`, or native resume coordinator owns the run.
>        - In `sweepOrphanedActiveLeases`: check process and process-group liveness, skip live runs, and directly release local driver leases (`!lease.provider || lease.provider === "local"`) with status `"released"` and `cleanupStatus: "success"`.
>        - In `sweepPendingCleanupLeases`: directly release local driver leases instead of failing on unsupported teardown.
>        - Wire `releaseEnvironmentLeasesForRun` into `recoveryService`.
> 3. **Verify:**
>    - Regression tests in `server/src/__tests__/release-cancelled-interrupted-run-leases.test.ts`:
>      1) In-process completion releases leases.
>      2) Operator/reassignment cancellation releases leases.
>      3) Stale-lock sweep backstop releases leases when owning process died.
>      4) Stranded terminal run lease is released by supported sweep.
>      5) Lease whose run's process is still alive is not released.

### Issue Summary: Environment leases of terminal runs remain active or stranded in failed state

**What happened?**
When an agent run was cancelled by an operator, cancelled on reassignment, or terminalized by the stale-lock sweep backstop after a server crash, its environment lease was never released and remained in `active` state with `releasedAt: null`. When `sweepOrphanedActiveLeases` (PR #13515) moved such leases to `pending_cleanup`, local environment driver leases could not be cleaned up because `sweepPendingCleanupLeases` threw `Environment driver "local" does not support orphan sandbox teardown` and marked the lease `failed` with `releasedAt: null`. Furthermore, `sweepOrphanedActiveLeases` did not verify whether the run process was still alive before moving leases to `pending_cleanup`.

**What did you expect to happen?**
1. Once execution stops, environment leases are released on every terminalizing path: in-process completion, operator/reassignment cancellation, and stale-lock recovery sweep.
2. Leases already stranded on terminal runs with no live process are cleanly released by supported sweeps without manual database edits.
3. Leases of runs whose process or process group is still alive are never released prematurely.

**Steps to reproduce**
1. Start an agent run configured with a local environment lease.
2. Cancel the run while active or terminate the server process.
3. Observe the lease remaining `active` with `releasedAt: null`, or transitioned to `pending_cleanup` and failing with `Environment driver "local" does not support orphan sandbox teardown`.

## What Changed

- `server/src/services/environments.ts`:
  - Extended `releaseLeasesForRun` to query both `active` and `pending_cleanup` leases, and support optional `cleanupStatus` and `failureReason`.
- `server/src/services/environment-runtime.ts`:
  - In `releaseRunLeases`, ensure active and pending leases are released with `cleanupStatus: "success"` even when no active runtime driver is instantiated.
- `server/src/services/recovery/service.ts`:
  - Added `releaseEnvironmentLeasesForRun` dependency and called it in `terminalizeOrphanedRunningRunCandidate` when backstop recovery terminalizes an orphaned run.
- `server/src/services/heartbeat.ts`:
  - In `cancelRunInternal`, call `releaseEnvironmentLeasesForRun` after cancellation settles.
  - In `releaseEnvironmentLeasesForRun`, guard against releasing while run process, process group, or native resume ownership is active.
  - In `sweepOrphanedActiveLeases`, check process liveness before transitioning leases and directly release local provider leases.
  - In `sweepPendingCleanupLeases`, directly release local provider leases with `cleanupStatus: "success"`.
  - Injected `releaseEnvironmentLeasesForRun` into `recoveryService`.
- `server/src/__tests__/release-cancelled-interrupted-run-leases.test.ts`:
  - Added comprehensive regression test suite covering in-process completion, operator cancellation, stale-lock sweep backstop, supported orphaned lease sweep, and live process lease preservation.

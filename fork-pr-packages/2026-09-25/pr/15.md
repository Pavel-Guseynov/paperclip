# fix(tool-gateway): gate context tools and capabilities by token allowedActions

## Thinking Path

> - Paperclip provides a named MCP tool gateway (`/mcp/gateways/:gatewayId` and `/api/tool-gateway/gateways/:gatewayId/mcp`) allowing agents and external clients to interact with registered MCP tools, resources, and prompts.
> - In `initialize`, the gateway unconditionally advertised `capabilities: { tools: {}, resources: {}, prompts: {} }`.
> - In `tools/list`, the gateway unconditionally appended four built-in context tools to every listing: `paperclip_list_resources`, `paperclip_read_resource`, `paperclip_list_prompts`, and `paperclip_get_prompt`.
> - However, gateway bearer tokens carry granular `allowedActions`. Specifically, per-run tokens minted by the heartbeat runtime authorize only `["tools/list", "tools/call"]`.
> - When an agent connected to the gateway, it saw `resources` and `prompts` capabilities and the four context tools advertised, but calling any of them failed with 403 `gateway_token_action_denied` ("Gateway bearer token is not allowed to perform this MCP action: rejected by transport: Forbidden").
> - An MCP gateway should never advertise operations or tools that the presented bearer token cannot perform.
> - This pull request gates context tools in `tools/list` and capabilities in `initialize` by the token's `allowedActions`:
>   - `paperclip_list_resources` requires `resources/list`
>   - `paperclip_read_resource` requires `resources/read`
>   - `paperclip_list_prompts` requires `prompts/list`
>   - `paperclip_get_prompt` requires `prompts/get`
>   - `capabilities.resources` requires `resources/list` or `resources/read`
>   - `capabilities.prompts` requires `prompts/list` or `prompts/get`
> - Unrestricted tokens (or tokens granting all six actions) retain full discovery and execution parity.

### Drafted Bug Report: Named MCP gateway advertises context tools and resource/prompt capabilities forbidden by bearer token allowedActions

**What happened?**
When an agent or client connects to a named MCP gateway (`/mcp/gateways/:gatewayId`) using a run-scoped bearer token (minted with `allowedActions: ["tools/list", "tools/call"]`), `initialize` advertises `resources: {}` and `prompts: {}` capabilities, and `tools/list` advertises four context tools (`paperclip_list_resources`, `paperclip_read_resource`, `paperclip_list_prompts`, `paperclip_get_prompt`).
When the agent invokes any of these four advertised tools, the gateway rejects the invocation with HTTP 403 `gateway_token_action_denied`:
`Gateway bearer token is not allowed to perform this MCP action: rejected by transport: Forbidden`.

**What did you expect to happen?**
The gateway should never advertise an operation or capability the presented bearer token cannot perform:
1. `initialize` advertises `resources` capability only when the token permits `resources/list` or `resources/read`.
2. `initialize` advertises `prompts` capability only when the token permits `prompts/list` or `prompts/get`.
3. `tools/list` includes each built-in context tool only when the token's `allowedActions` includes its mapped action.
4. Tokens that allow all six actions (or default unrestricted tokens) continue to see all four context tools and both capabilities.

**Steps to reproduce**
1. Mint a named gateway token scoped to a run with `allowedActions: ["tools/list", "tools/call"]`.
2. Call `initialize` on `/mcp/gateways/:gatewayId`. Observe `resources: {}` and `prompts: {}` in capabilities.
3. Call `tools/list` on `/mcp/gateways/:gatewayId`. Observe `paperclip_list_resources`, `paperclip_read_resource`, `paperclip_list_prompts`, and `paperclip_get_prompt`.
4. Call `tools/call` with `paperclip_list_resources`. The call is rejected with HTTP 403 `gateway_token_action_denied`.

**Paperclip version or commit**
`master` at `efce9356b553a08f77a5877bb0ceac68d2cc4ad8` and release tag `v2026.916.1`.

**Deployment mode**
Self-hosted server and cloud instances.

## What Changed

- `server/src/services/tool-gateway.ts`:
  - Updated `listToolsForNamedGateway` return value to attach `{ tools, allowedActions }` using `Object.assign([...tools], { tools, allowedActions })`, retaining complete backwards compatibility for existing array consumers while providing token action context to routes.
- `server/src/routes/tool-gateway.ts`:
  - In `handleMcpGatewayProtocol` for `initialize`: dynamically construct `capabilities` so `capabilities.resources` is only advertised if `allowedActions` permits `resources/list` or `resources/read`, and `capabilities.prompts` is only advertised if `allowedActions` permits `prompts/list` or `prompts/get`.
  - In `handleMcpGatewayProtocol` for `tools/list`: filter built-in context tools (`paperclip_list_resources`, `paperclip_read_resource`, `paperclip_list_prompts`, `paperclip_get_prompt`) by token `allowedActions`.
- `server/src/__tests__/tool-gateway.test.ts`:
  - Added regression test `gates gateway context tools and capabilities by token allowedActions`:
    1. Verifies run-scoped token (`tools/list`, `tools/call`) receives `{ tools: {} }` capabilities and none of the four context tools in `tools/list`.
    2. Verifies full token (all six actions) receives all capabilities, sees all four context tools, and successfully calls them.
    3. Verifies partial action tokens (e.g. only `prompts/list` or only `resources/read`) receive exactly matching capabilities and context tools.

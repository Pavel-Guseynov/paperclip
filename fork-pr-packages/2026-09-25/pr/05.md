## Thinking Path

> - Paperclip is the open source app people use to manage AI agents for work
> - The server logs HTTP requests, errors, and service events with pino, and operators ship these logs to external systems
> - Agents authenticate to the tool gateway with `pcgw_*` and `pcgt_*` bearers, and several `X-Paperclip-*` headers carry credentials
> - The HTTP logger redacts a fixed list of header paths, but that list does not include `x-paperclip-tool-gateway-token`. Credentials in child-logger bindings, nested log fields, serialized errors (including their `cause` chains), and response headers are not redacted (#4759)
> - So a gateway token can reach the logs on success, on rejected authentication, and on downstream failures
> - This pull request derives the redaction from one credential authority and applies it to every log path: request and response headers, child bindings, nested fields, error messages and causes, and HTTP objects that reach a log record
> - The benefit is that tool gateway credentials never appear in the server logs, while safe diagnostics stay (phase, status, mechanism, and header presence)

## What Changed

- `server/src/middleware/http-log-redaction.ts`:
  - One exported credential authority, `CREDENTIAL_HEADER_NAMES` plus `CREDENTIAL_LOG_FIELD_NAMES`. `HTTP_LOG_REDACT_PATHS` is derived from it. It keeps all of upstream's paths (a strict superset), and it cannot contain duplicates.
  - Credential names match in every separator spelling, for example `proxy-authorization`, `proxy_authorization`, and `proxyAuthorization`.
  - `sanitizeCredentialText()` redacts `pcgw_`/`pcgt_` tokens and auth-scheme credentials in free text. It keeps prose such as "Bearer authorization header".
  - `sanitizeErrorObject()` runs after pino's standard error serializer. So `cause` chains stay, arrays stay arrays, and cycles and depth are bounded.
  - HTTP objects that reach a log record under any key other than `req`, `res`, or `err` are replaced by a safe summary (`type`, `method`, `statusCode`).
- `server/src/middleware/logger.ts`:
  - `basePinoOptions` adds the derived redact paths, the header and error serializers, and a `logMethod` hook.
  - The hook rewrites credential text in messages and redacts credential-named fields at any depth. It copies only when it changes something, so ordinary records are not cloned.
  - A field whose getter throws becomes `[Unreadable]` for that field only. The rest of the record is still redacted, and a log call never throws. A proxy trap that throws while the walk checks for an `Error` or an HTTP object makes the walk read the record field by field instead of passing it through.
  - Response headers are redacted, including unlisted headers whose names look like credentials.
- `server/src/middleware/redact-sensitive.ts`: key-based redaction uses the same authority. Strings are credential-sanitized.
- `server/src/middleware/error-handler.ts` and the tool gateway routes do not change. HTTP response bodies keep upstream's contract.
- `server/src/__tests__/http-log-redaction.test.ts`: sentinel tests through the real production logger configuration (`basePinoOptions`). They cover:
  - 200, 401, 500, and downstream failures
  - mixed-case headers, and unlisted credential-shaped headers
  - child bindings, and nested fields
  - `cause` chains, cyclic and array-valued error properties
  - stray HTTP objects
  - that non-credential fields keep their values

## Risks

- Credential-named fields at any depth of a log record are now redacted. A field with a credential-like name that is not a credential is also redacted. The list is closed and documented.
- Free-text redaction can mask some auth-scheme prose. A closed list of known non-credential words stays readable, and there are tests for it.
- The per-log cost is one shallow scan of the merge object. Ordinary records are not cloned.

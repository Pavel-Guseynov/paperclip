## Thinking Path

> - Paperclip is the open source app people use to manage AI agents for work
> - Agent processes call back into the Paperclip API and MCP endpoints, and the server tells them where through `PAPERCLIP_API_URL`
> - The public dashboard URL is often not reachable from where the agent runs, for example a VPN or tailnet URL, or a sandbox that sees the host through a bridge (#3802, #11203)
> - An operator can pin `PAPERCLIP_RUNTIME_API_URL` for the internal callback. But the server overwrites the pin at startup, and the adapters never give agents a separate internal callback URL (#6630, #8130)
> - This pull request keeps a pinned internal callback URL and passes it to agents as `PAPERCLIP_RUNTIME_API_URL`, separate from the public `PAPERCLIP_API_URL`. The consumers that dial the server use it: Codex CLI MCP config, the Paperclip CLI, heartbeat MCP URLs, the artifact upload script, and the sandbox and SSH bridge
> - The benefit is that operators can give agents a reachable callback origin without changing the URL that people see

## What Changed

- `server/src/index.ts`, `server/src/runtime-api.ts`: a pre-set `PAPERCLIP_RUNTIME_API_URL` is kept and leads the runtime candidate list. The public API URL stays in the list after it. Without a pin, the runtime URL is the effective `PAPERCLIP_API_URL`, so an operator's `PAPERCLIP_API_URL` override still wins over a URL derived from `authPublicBaseUrl`.
- `packages/adapter-utils/src/server-utils.ts`: `buildPaperclipEnv()` also emits `PAPERCLIP_RUNTIME_API_URL`. The precedence is `PAPERCLIP_RUNTIME_API_URL`, then `PAPERCLIP_API_URL`, then the bound listen host and port. The public `PAPERCLIP_API_URL` it emits keeps upstream's precedence exactly.
- `packages/adapter-utils/src/execution-target.ts`: the sandbox bridges (`queue_v1` and `http2_v1`) also export `PAPERCLIP_RUNTIME_API_URL` with their in-target origin.
- `packages/adapters/codex-local/src/server/execute.ts`: managed MCP URLs in `config.toml` use the internal callback origin.
- `server/src/services/heartbeat.ts`: gateway and project-tools MCP URLs use the internal origin. The gate that decides whether runtime tools are delivered does not change.
- `packages/adapters/cursor-cloud/src/server/execute.ts`: `PAPERCLIP_RUNTIME_API_URL` is also removed when the cloud worker cannot reach the host, the same as `PAPERCLIP_API_URL`.
- `cli/src/commands/client/common.ts`: `resolveApiBase` uses `--api-base`, then `PAPERCLIP_RUNTIME_API_URL`, then `PAPERCLIP_API_URL`, then the profile.
- `skills/paperclip/scripts/paperclip-upload-artifact.sh` prefers the runtime URL.
- Docs: `doc/CLI.md` (API base precedence) and `doc/AGENT-ARTIFACTS.md` (environment variables).

Not in scope (non-goals): ACP-mode managed MCP delivery, a separate origin for container namespaces, and MCP reachability from sandbox or SSH guests. The last one needs a cross-namespace authentication design, and this pull request does not change the sandbox callback bridge's authentication. `sandbox-callback-bridge.ts` and `http2-bridge-server.ts` do not change.

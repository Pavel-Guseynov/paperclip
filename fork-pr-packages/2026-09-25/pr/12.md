## Thinking Path

> - Paperclip is the open source app people use to manage AI agents for work
> - Agents run their dev servers as managed workspace runtime services, and the server allocates their loopback ports
> - The server tests start many of these runtime services in one Vitest worker
> - `resetRuntimeServicesForTests()` clears the runtime maps between tests, but it does not clear the in-flight port claims, which live for 120 seconds
> - Also, the contiguous-port fixture picks its base port from the OS ephemeral range, and the two HTTPS exposure lifecycle tests share one execution workspace id
> - Together these let one test's ports and identity leak into the next test, and the aggregate server run failed with `EADDRINUSE` on an HMR companion port
> - This pull request clears the in-flight claims in the standard test reset and isolates the fixtures
> - The benefit is a deterministic server test run that does not depend on test order or on unrelated loopback traffic

## Linked Issues or Issue Description

No issue exists. This is the bug report, in the shape of `.github/ISSUE_TEMPLATE/bug_report.yml`.

**What happened?**
A complete server test run failed in the workspace HTTPS exposure lifecycle tests. The second lifecycle test got `EADDRINUSE` on HMR companion port 52000. A later diagnostic found no listener, so the other process was not identified.

**What did you expect to happen?**
Each test starts from a clean port and identity state, whatever ran before it in the same worker.

**Steps to reproduce**
1. In one Vitest worker, call `claimRuntimeServiceBindPort(25100, null)`.
2. Call `resetRuntimeServicesForTests()`.
3. Call `claimRuntimeServiceBindPort(25100, null)` again. It returns `false`, because the reset did not clear `inFlightAllocatedPorts`. The claim stays for its 120-second TTL.

**Paperclip version or commit**
`master` at 7b7c4d4172d6aac14919e2682b702ae87bc17653.

**Deployment mode**
Local test runs (macOS and Linux). No production path calls `resetRuntimeServicesForTests()`.

## What Changed

- `server/src/services/workspace-runtime.ts`: `resetRuntimeServicesForTests()` also calls `resetRuntimeServicePortReservationsForTests()`. This is the only production-file change, and only test code calls this function.
- `server/src/__tests__/workspace-runtime-start-terminality.test.ts`: new regression test. A claim made before the reset is released by the reset.
- `server/src/services/workspace-runtime-exposure.test.ts`: the two HTTPS exposure lifecycle tests use distinct `randomUUID()` execution workspace ids. They keep automatic port allocation and the `>= 42000` assertion unchanged.
- `server/src/__tests__/workspace-runtime.test.ts`: `reserveContiguousPorts` scans the fixture range 25000–32000. This range is below the Darwin (49152+) and Linux (32768+) ephemeral ranges, and it does not overlap the exposure ranges 42000–42999 and 52000–52999. It no longer uses an OS-assigned base port.
